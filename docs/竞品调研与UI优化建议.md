## 二、差距分析：我们还能优化什么

按「投入产出比」排序，P0 是强烈建议做的。

### P0 — 检索质量与阅读体验（决定产品是否"能用"）

| # | 优化项 | 现状 | 做法 |
|---|--------|------|------|
| 1 | **混合检索（BM25 + 向量）** | 仅向量（无 embedding 时降级关键词），无融合 | 同时跑关键词与向量召回，用 **RRF**（k=60）融合排序，成本低、对课程专有名词召回提升明显 |
| 2 | **切块策略升级** | 固定 900 字符硬切 | PPTX 按页、DOCX 按标题层级、PDF 按段落；每块附带「文档名 + 页码/章节」上下文前缀（Contextual Retrieval） |
| 3 | **阅读器内查找 Ctrl+F** | 只有文库页搜索 | 阅读器内搜索原文 + 译文，显示匹配数、高亮命中、上下切换 |
| 4 | **原页跟随定位** | 翻译是对照列表，无原页联动 | 翻译面板加「原页面板」，滚动时同步翻页并框出当前段落在原页位置（easyread 的招牌交互） |

### P1 — AI 差异化（决定产品是否"好用"）

| # | 优化项 | 说明 |
|---|--------|------|
| 5 | **一键生成学习制品** | 对当前课件生成：知识大纲 / 思维导图 / 闪卡 / 练习题（带出处），存回该知识库。这是 NotebookLM 系最打动学生的功能，我们有 RAG 基础，实现成本不高 |
| 6 | **引用相关度评分** | 每条引用给 0–100 相关度，低于阈值时回答顶部提示「课件中未找到强相关内容，以下含网络补充」，防止幻觉（Kotaemon 做法） |
| 7 | **问答源可视化** | 回答下方列出「本次参考了哪些课件、哪些页」，可点击勾选排除某份文档后重问 |
| 8 | **多文档对比问答** | 「对比第 3 讲和第 7 讲对 X 的说法」，走跨库检索 + 对比式提示词 |

### P2 — 工程与协作（决定产品是否"能长期用"）

| # | 优化项 | 说明 |
|---|--------|------|
| 9 | **大文件分片上传 / 断点续传** | 云存储分片，避免大课件上传失败重来 |
| 10 | **解析失败重试与状态机** | easyread 有「后台翻译 + 失败重试/跳过」；我们的 ingest 应记录状态并显示进度 |
| 11 | **知识库共享 / 协作** | 课程库生成只读分享链接（同学之间共用一库），这是学生场景强需求 |
| 12 | **标注导出为图片/PDF 快照** | 目前 PDF 烧录 + HTML；可加「导出当前页为 PNG」 |
| 13 | **移动端适配** | 触屏手写已有，但工具栏与面板在窄屏需折叠 |

## 三、UI 资源推荐

### 3.1 关键约束先说清楚

我们当前是**零构建纯静态**（HTML + 原生 JS + CDN）。这意味着：
- ❌ **shadcn/ui、Magic UI、Aceternity UI** 都是 React + Tailwind 的「复制粘贴组件」，直接引入需要 React 运行时和 Tailwind 编译链，**不能直接用**
- ✅ 但可以**抄它们的设计 token 和交互规范**，用原生 CSS/JS 实现，效果能到 80%

### 3.2 可直接 CDN 引入（零构建友好）⭐

| 资源 | Stars | 用途 | CDN |
|------|-------|------|-----|
| **Lucide Icons** | ~22k | 统一图标语言，替换现在混杂的 emoji/自绘 SVG | `unpkg.com/lucide@latest/dist/umd/lucide.js` → `lucide.createIcons()` |
| **Open Props** | ~3k | CSS 变量工具包：缓动曲线、阴影、渐变、色板 | `unpkg.com/open-props` |
| **Motion One** | ~10k | 原生 JS 动画引擎（比 Framer Motion 轻，不需要 React） | `unpkg.com/motion` |
| **KaTeX** | ~20k | 公式渲染——**数学类课件刚需** | `cdn.jsdelivr.net/npm/katex` |
| **perfect-freehand** | 5.8k | 手写笔迹平滑 + 压感 | `unpkg.com/perfect-freehand` |

### 3.3 参考其设计（需手写实现）⭐⭐

| 资源 | Stars | 抄什么 |
|------|-------|--------|
| **shadcn/ui** | 125,866 | ① HSL CSS 变量体系（`--background/--foreground/--primary/--muted/--border/--ring/--radius`）② 8px 栅格 + 统一圆角 ③ 焦点环 `--ring` ④ 极克制的阴影与过渡 |
| **Magic UI** | ~21k | 微交互质感：shimmer、渐显、数字滚动、bento 网格 |
| **Aceternity UI** | ~28k | 深色模式的高级感：spotlight、glow 边框、3D 卡片（**慎用**，偏营销页，工作台里要克制） |
| **HeroUI** / **Mantine** | 29k / 31k | 组件交互规范：popover、tooltip、drawer、command palette |
| **tldraw** | 50,977 | 手写/画布的交互标杆：笔迹预测、压感、撤销重做、平移缩放手感 |

### 3.4 具体可落地的改造清单（不改架构）

1. **图标统一到 Lucide** — 现在工具栏混用自绘 SVG 和 emoji，风格不统一
2. **设计 token 化** — 把 `style.css` 顶部的变量重构为 shadcn 风格 HSL 体系（`hsl(var(--x))`），一次改全局生效
3. **命令面板 Cmd/Ctrl + K** — 自研约 100 行：跳课件、切知识库、切工具、执行总结
4. **Toast 升级** — 对齐 Sonner 的视觉（堆叠、图标、描边、进度）
5. **卡片交互** — hover 抬升 + 边框渐显 + 骨架屏 + 空状态插画
6. **工具栏** — 统一为 segmented control，当前工具高亮
7. **快捷键帮助面板** — 按 `?` 弹出
8. **过渡曲线统一** — 用 `cubic-bezier(0.32, 0.72, 0, 1)`（shadcn / Vercel 风格），150–200ms

## 四、路线建议

```
M5  UI 现代化（设计 token + Lucide + 命令面板 + 微交互）   ← 建议先做，见效最快
M6  检索质量（混合检索 RRF + 上下文切块 + 相关度评分）
M7  学习制品（大纲/思维导图/闪卡/练习题）
M8  协作与工程（分享链接 + 分片上传 + 移动端）
```

理由：UI 是用户第一眼能感知的，且改造风险低（纯 CSS/交互层，不动数据）；检索质量是后台能力，提升需要调试和评测，建议和 M7 一起做，因为它同时影响问答与制品生成的准确性。

---

## 五、一句话结论

我们的**功能覆盖面已经和主流开源项目持平**（多知识库、跨设备同步、双语翻译、RAG 引用、双类标注、导出），真正的差距在两处：**① 检索是"能跑"而非"准"（缺混合检索 + 重排 + 上下文切块）；② UI 是"能用"而非"好看"（缺统一设计 token 和图标语言）**。这两块补上，体验会跨一个档次。
