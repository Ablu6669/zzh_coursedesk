# 课件台 · 云端部署指南

> 部署完成后，课件台从「仅本机」变成真正的多设备应用：课件、标注、译文、索引全部存在云端，
> 手机 / 平板 / 电脑登录同一邮箱看到的内容完全一致。

## 架构一句话

前端（HTML/CSS/JS）放在**静态托管**或 **GitHub Pages**，后端是 5 个**云函数** + **云数据库** + **云存储**。
「静态」只指前端不需要 npm 打包，业务逻辑和全部数据都在云端，是标准 Serverless 动态应用。

```
设备 A / B / C  ──加载页面──▶  静态托管 / GitHub Pages（只有 index.html + css/ + js/）
                                    │ REST 请求（HTTP 访问服务，带 CORS）
                                    ▼
              云函数(cd-login/cd-data/cd-ingest/cd-ask/cd-translate) + 云数据库 + 云存储 + 混元LLM
```

### ⚠️ 关键设计：为什么走「HTTP 访问服务」而不是默认的 SDK 调用

| 方案 | 依赖匿名登录 | 依赖安全域名白名单 | 体验版可用性 |
|------|------------|------------------|-------------|
| 默认 SDK 调用 `app.callFunction` | **必须开启** | 要求域名在白名单内 | 匿名登录默认关闭；体验版**无法通过 CLI/API 添加安全域名**（报「当前套餐无法执行此操作」） |
| **HTTP 访问服务 + REST** ✅ | 不需要 | 不需要 | **完全可用**，任意托管域（含 GitHub Pages）都能直连 |

因此本项目给每个云函数都加了 HTTP/CORS 适配层，前端优先走 `https://<域名>/cd/<name>` 的 REST 通道，
只有文件上传/下载（云存储）才需要 SDK，而 SDK 需要环境开启匿名登录。

> 免费体验版的两个限制（已实测，2026-10-19）：
> 1. `tcb cors add` / `createEnvDomain` 均返回「当前套餐无法执行此操作」→ 安全域名加不了，必须走 HTTP 访问服务；
> 2. `CreateLoginConfig` API 返回成功但实际不生效 → **匿名登录必须在控制台手动开启**（环境 → 登录授权 → 匿名登录）。
>    开了之后 SDK 模式的文件上传/下载才能用；不开的话除了文件上传，其余功能走 HTTP 通道均正常。

## 第 1 步 · 开通云开发环境

**方式 A · 免费体验版（¥0，推荐）**

1. 微信关注公众号「**腾讯云开发 CloudBase**」，在对话框发送「**领取兑换码**」，获得一次性兑换码（每账号限 1 个，领取后 30 天内有效）
2. 打开 [CloudBase 控制台](https://tcb.cloud.tencent.com/) → **新建环境** → 套餐选「免费体验版」，填入兑换码
3. 免费版每月 3000 资源点（≈15 万次数据库调用），单次可续 6 个月，到期前 1 个月内可续期
4. 省点技巧：翻译/AI 问答的 LLM Key 在课件台「设置」里直连（本地模式同款配置），Token 走自己的 Key，不消耗资源点

**方式 B · 个人版（¥19.9/月，40,000 资源点）**

在 [购买页](https://buy.cloud.tencent.com/CloudBase) 购买。注意把默认的「连续包月」改成「1 个月」先试用。适合免费点数不够用或想长期稳定运行时再升。

**无论哪种方式，记下环境 ID**（形如 `coursedeck-3g1a2b4c`）。

## 第 0 步 · 与其他项目共用环境（命名空间隔离）

课件台所有云端资源都带前缀，可与其他项目安全共用同一个 CloudBase 环境（例如 `zzhscheduler`）：

| 资源 | 命名规则 |
|------|---------|
| 云函数 | `cd-login` / `cd-data` / `cd-ingest` / `cd-ask` / `cd-translate` |
| 数据库集合 | `cd_users` / `cd_logincodes` / `cd_sessions` / `cd_libs` / `cd_docs` / `cd_annots` / `cd_trans` / `cd_chunks` |
| 云存储路径 | `coursedeck/<用户邮箱>/<文档id>.<格式>` |
| 静态托管 | 子路径 `/coursedeck/`（不占用根路径，不影响其他项目的站点） |

注意：免费体验版每账号限 1 个环境，共用环境意味着两个项目共享每月 3000 资源点额度。

## 第 2 步 · 创建数据库集合

在「数据库」页新建以下 8 个集合（名字必须完全一致）：

| 集合 | 用途 | 写入方 |
|------|------|--------|
| `cd_users` | 用户档案 | cd-login |
| `cd_logincodes` | 邮箱验证码 | cd-login |
| `cd_sessions` | 登录会话（30 天有效） | cd-login |
| `cd_libs` | 知识库 | cd-data |
| `cd_docs` | 课件元数据 | cd-data |
| `cd_annots` | 高亮 / 手写标注 | cd-data |
| `cd_trans` | 翻译缓存 | cd-data |
| `cd_chunks` | RAG 切块与向量 | cd-ingest |

**权限建议**（正式上线前务必收紧）：先设为「仅管理端可读写」，因为所有读写都经过云函数，
云函数用 admin 权限操作数据库，前端不直连。

**索引建议**（数据量大后必需）：`cd_sessions` 建 `email + token`；`cd_docs`/`cd_annots`/`cd_chunks`/`cd_trans`
建 `email + docId`；`cd_chunks` 额外建 `email + id`。

## 第 3 步 · 部署 5 个云函数

### 方式 A：命令行（推荐）

```bash
npm install -g @cloudbase/cli
tcb login
cd coursedeck
# 先把 cloudbaserc.json 里的 envId 改成你的环境 ID
tcb fn deploy cd-login
tcb fn deploy cd-data
tcb fn deploy cd-ingest
tcb fn deploy cd-ask
tcb fn deploy cd-translate
```

> Windows 上若提示「无法加载 npm.ps1」，改用 `npm.cmd install -g @cloudbase/cli`。

### 方式 B：控制台手动上传

云函数 → 新建函数 → 函数名填 `cd-login` 等（与目录名一致）→ 函数类型「事件函数」→ 运行环境 Node.js 16+ →
把对应目录（`cloudfunctions/<函数名>/`）打包上传，入口填 `index.js`。
每个函数**必须安装依赖**：上传时勾选「自动安装依赖」，或本地 `npm install` 后连同 `node_modules` 一起打包。

## 第 4 步 · 配置环境变量

在云函数的「函数配置 → 环境变量」里添加：

| 函数 | 变量 | 说明 |
|------|------|------|
| `cd-login` | `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `SMTP_FROM` | 发验证码的邮箱。QQ 邮箱：`smtp.qq.com` / `465` / 授权码 |
| `cd-ingest` | `LLM_KEY` `LLM_BASE` `EMBED_MODEL` | 向量化。`LLM_BASE` 默认 `https://api.hunyuan.cloud.tencent.com/v1` |
| `cd-ask` | `LLM_KEY` `LLM_BASE` `LLM_MODEL` `EMBED_MODEL` `SERPER_KEY` | 问答；`SERPER_KEY` 不填则不联网 |
| `cd-translate` | `LLM_KEY` `LLM_BASE` `LLM_MODEL` | 全文翻译 |
| `cd-data` | 无需 | 只做鉴权与读写数据库 |

- `LLM_KEY` 在[混元大模型控制台](https://cloud.tencent.com/product/hunyuan)获取
- `LLM_MODEL` 建议 `hunyuan-turbos-latest`，`EMBED_MODEL` 建议 `hunyuan-embedding`
- **不配 `SMTP_*` 也能用**：验证码会打印到云函数日志里，方便先跑通链路

## 第 5 步 · 配置安全域名

「安全配置 → Web 安全域名」中加入你访问页面的域名。
本地调试加 `http://127.0.0.1:8137`，正式环境加静态托管给你的默认域名。
**漏掉这一步会表现为「发送验证码失败 / 云函数调用被拒」。**
共用环境时注意：这里加的域名是全环境共享的白名单，不影响其他项目。

## 第 6 步 · 部署前端静态托管

```bash
tcb hosting deploy dist /coursedeck/ -e 你的环境ID
```

访问地址为 `https://<默认域名>/coursedeck/`。子路径部署不会动根路径上已有的其他项目文件。
**只上传 `index.html + css/ + js/`**（deploy/setup.js 的 buildDist 已保证），云函数源码与密钥配置绝不上行。

## 第 7 步 · 连接并验证

1. 打开页面 → 右上角齿轮 → 填入**环境 ID** → 点 **测试连接**
   - 看到「连接正常：云环境可达，cd-data 云函数已部署」即可保存
2. 回到登录页 → 输入邮箱 → 发送验证码 → 登录
3. 顶栏徽章应变为绿色 **「多设备同步 · 你的邮箱」**，文库顶部状态条同步变为云端模式
4. **多设备验证**：手机浏览器打开同一网址，登录同一邮箱，应看到完全相同的知识库与课件

## 故障排查

| 现象 | 原因 / 处理 |
|------|------------|
| 云函数返回 `FUNCTIONS_INVOCATION_FAILED` / `0 code exit unexpected` | **依赖没装上**。云端自动安装依赖经常失败，改为在每个函数目录本地 `npm install`，让 node_modules 随包上传（本项目已这么做） |
| `Directory for function [x] not found: functions/x` | `cloudbaserc.json` 缺 `functionRoot: "cloudfunctions"`。重跑 `node deploy/setup.js` 会自动带上 |
| 静态托管上传报 `Access Denied`（连 `tcb hosting list` 都失败） | 子账号缺 COS 数据权限。给子账号补对象存储权限，或改用主账号 / 直接在控制台网页上传；本项目主走 GitHub Pages，腾讯云托管只是备选 |
| `tcb cors add` 报「当前套餐无法执行此操作」 | 体验版不支持自定义安全域名，属正常限制 → 走 HTTP 访问服务即可，无需白名单 |
| 测试连接报「函数名不存在」 | 云函数没部署成功，回第 3 步检查（注意函数名是 `cd-` 前缀） |
| 能连上但收不到验证码 | 没配 SMTP（去看 cd-login 云函数日志，验证码会打在里面）；或 SMTP 授权码用了登录密码 |
| 验证码正确但登录失败 | 检查 `cd_sessions` 集合是否存在 |
| 登录后看不到课件 | 检查 `cd_docs`/`cd_libs` 集合是否存在，以及 `email` 字段是否写入 |
| AI 问答报模型错误 | `LLM_KEY` 或 `LLM_MODEL` 配错，混元密钥需在该环境可用 |
| 手机能登录但打不开课件 | 云存储权限需允许读取；检查 `cd_docs.fileID` 是否有值 |
